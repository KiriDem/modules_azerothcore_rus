## mod-ah-bot-plus

## Описание

Это форк бота для аукциона, предназначенного для AzerothCore. Данная версия обеспечивает гораздо более аутентичный (в духе Blizzard) ассортимент товаров на аукционе и разработана с учетом следующего принципа: «Максимально понятная настройка для администраторов с использованием конфигурационных файлов, не требующих правки SQL-запросов». Вот некоторые ключевые особенности:
 - Вся настройка выполняется через конфигурационные файлы; настройка SQL не требуется.
 - Функция управления списком, позволяющая задавать правила включения или исключения элементов, определять пропорции категорий, управлять размером стека и т.д.
 - Полностью настраиваемая и предсказуемая система ценообразования, которая может учитывать категорию, подкатегорию, качество, уровень товара и т.д.
 - Дополнительные продвинутые правила расчета цен для тех, кому нужно более готовое решение, максимально приближенное к официальному (Blizzlike).
 - Настраиваемый бот для покупок, поведение которого может варьироваться от честного (как у бота для продаж) до скупого или жадного.
 - Поддержка нескольких ботов для аукциона, позволяющая использовать разнообразные названия лотов.
 - Команды ГМ для быстрой настройки: перезагрузка конфигураций и обновление аукционов.
 - Множество функций для повышения удобства использования, не удостоившихся отдельной строки в этом списке.

## Требования
Требуется версия AzerothCore, актуальная как минимум до набора изменений 3f46e05.
(https://github.com/azerothcore/azerothcore-wotlk/commit/3f46e05d3691895b6b8a5b3832d17ecb1e210791)

## Установка

```
1. Просто поместите модуль в директорию `modules` исходного кода AzerothCore. 
2. Запустите cmake повторно и выполните чистую сборку AzerothCore.
```

## Использование

**Прежде чем что-либо предпринимать, создайте хотя бы одного персонажа, который будет использоваться в качестве бота.**.  Отредактируйте конфигурацию модуля и **добавьте один или несколько GUID персонажей в переменную «AuctionHouseBot.GUIDs»** эти идентификаторы берутся из таблицы персонажей в базе данных персонажей. Эти имена будут видны на аукционе, поэтому выбирайте их тщательно. ВАЖНО: Если вы используете мод для добавления ботов (например, playerbots), убедитесь, что для работы с аукционом вы используете обычных персонажей, а не ботов. После этого убедитесь, что вы установили **AuctionHouseBot.EnableSeller = true**. Больше ничего не требуется, если только вы не хотите изменить настройки или включить бота-покупателя, что делается с помощью AuctionHouseBot.Buyer.Enabled.

Примечания:
- Для этих учетных записей не требуется определенный уровень доступа (security level) это могут быть обычные аккаунты игроков.
- Персонажи, используемые ботом аукциона (ahbot), не предназначены для игры. Если вы попытаетесь использовать такого персонажа для просмотра аукциона, могут возникнуть проблемы — например, сообщение «Поиск предметов...» (Searching for items...) может отображаться бесконечно.
- Для полного заполнения аукциона товарами требуется несколько часов, так как по умолчанию за один «тик» (цикл обновления) добавляется всего 75 предметов. Этот параметр можно изменить в файле конфигурации с помощью переменной `AuctionHouseBot.ItemsPerCycle`.
- Все множители цен (включая настройки расширенного ценообразования, см. конфигурацию) применяются мультипликативно (перемножаются).
Пример: множители 1,5x для категории, 2x для качества и 1,4x для сочетания категории и качества дадут итоговый множитель 4,2 (1,5 × 2 × 1,4). Затем полученное значение дополнительно умножается согласно настройкам расширенного ценообразования. Множители цен, зависящие от уровня предмета (создающие множитель вида «уровень предмета × значение»), также применяются мультипликативно наряду с остальными. Нельзя одновременно использовать множители цен по уровню предмета и расширенное ценообразование, так как приоритет будет отдан расширенному ценообразованию.
- Цены, устанавливаемые ботом, не превышают 100 000 золотых (цена выкупа). При необходимости этот лимит можно снизить в настройках конфигурации.

### Внутриигровые команды

Модуль AuctionHouseBot добавляет следующие внутриигровые команды (только для ГМ):

|  Команда | Описание     |
|----------|--------------|
| `.ahbot reload` | Перезагружает файл конфигурации AuctionHouseBot и обновляет настройки.. |
| `.ahbot empty` | Удаляет все аукционы AuctionHouseBot со всех аукционов.<br>Аукционы игроков не затрагиваются. Ставки на затронутые предметы возвращаются игрокам.<br>Использовать с осторожностью! |
| `.ahbot update` | Принуждает бота немедленно обновить или заново загрузить список лотов аукциона.<br>Примечание: Если между циклами покупки и продажи настроен интервал в несколько минут, возможно, потребуется запустить процесс несколько раз, прежде чем вы увидите результаты. |


## Поведение покупающих ботов

1. **Выбор товаров для покупки:** Каждую минуту бот-покупатель отбирает определенное количество (параметр `BuyCandidatesPerBuyCycle`) выставленных на аукцион лотов, которые были отмечены игроками как потенциально интересные для покупки.
2. **Определение цены покупки:** Бот-покупатель рассчитывает цену по тому же алгоритму, что и бот-продавец (включая случайное отклонение в пределах ±25%, которое можно настроить), а затем умножает полученное значение на коэффициент `AcceptablePriceModifier`. Итоговая сумма и становится ценой, которую бот готов заплатить.
3. **Процесс покупки:** Если рассчитанная цена превышает цену мгновенного выкупа, бот выкупает лот. В противном случае он проверяет, не сделал ли ставку другой бот; если нет — сравнивает текущую ставку с ценой, которую он готов заплатить. Если текущая ставка ниже этой цены, бот делает свою ставку (перебивая предыдущую, то есть предлагая сумму чуть выше текущей).

Описанный выше алгоритм работает для каждого активного аукционного дома. При использовании настроек по умолчанию система попытается купить один лот на каждом аукционе, если расчетная цена покажется выгодной. Обратите внимание: любая попытка покупки — даже если цена лота превышает целевой уровень — расходует лимит на выбор кандидатов для покупки. Это означает, что избыток переоцененных лотов может вытеснить потенциально выгодные сделки.
